# Audit de TOP1.Fit du 21 novembre 2026

Ce compte rendu décrit le déploiement vérifié le 21 novembre. Pour le fonctionnement du code de cette branche, consulter le [périmètre produit](PRODUCT_FOCUS.md).

## Produit et références

Le parcours principal permet de saisir 36 mesures dans six catégories, individuellement ou à la suite. Le profil regroupe les préférences, le compte et les contrôles de données. L’écran Potentiel, l’historique présenté dans le profil et les objets connectés sont annoncés pour plus tard.

Dans le catalogue actif, le moteur dispose de références publiées pour la VO₂ mesurée sur tapis selon le protocole prévu, la force de préhension et le saut vertical avec contre-mouvement. La comparaison dépend aussi de la cohorte et des informations disponibles sur le test. La saisie rapide conserve une méthode ou une date inconnue. Les paliers de défi TOP1 suivent des règles du produit. Cet audit vérifie le comportement du logiciel et la présentation des bornes. La validation scientifique des seuils demanderait une revue des études et de leurs populations. ## Correctifs vérifiés

| Parcours | Défaut observé | Correction |
| --- | --- | --- |
| Profil invité | Un enregistrement ou une création de profil pouvait remplacer des données locales illisibles. La lecture d’un ancien profil invité pouvait aussi bloquer l’affichage d’un compte valide. | Nouvelle vérification avant écriture. Réessai, export brut et suppression explicite sont accessibles. Le chargement du compte est indépendant de l’import invité. |
| Données privées | Une lecture pouvait utiliser la session désormais active dans un autre onglet et associer sa réponse à l’écran encore ouvert. | Les clients mis à jour indiquent le compte affiché. Le serveur le compare à l’utilisateur authentifié. Les anciens clients conservent leur compatibilité. |
| Suppression du compte sur mobile | Le chemin de révocation avec clé d’administration cherchait une session web alors que le client mobile présente un jeton. | Le serveur vérifie le jeton exact et son titulaire avant la révocation. Les essais utilisent des sessions simulées. |
| Mesures | Le signe « + » rendait la borne supérieure ambiguë. La valeur et l’unité manquaient dans la description accessible des cartes. Un âge saisi en chiffres arabes pouvait être signalé à tort en cas de mesure invalide. | La carte affiche « TOP 5 % ou mieux » lorsque le résultat dépasse le seuil publié du 95ᵉ percentile et expose les valeurs au lecteur d’écran. Les erreurs d’âge et de mesure sont distinctes. |
| Tractions lestées | Effacer une ancienne charge additionnelle nulle pouvait valider la saisie et conserver l’ancienne estimation. | Un zéro explicite est accepté, y compris en chiffres arabes. Une case vide demande de compléter la charge. |
| Paquet mobile | Le contrôle acceptait un HTML dont le JavaScript référencé manquait. Les copies iOS et Android pouvaient contenir une version antérieure. | Le contrôle vérifie les entrées du HTML et compare les fichiers attendus aux copies embarquées. Les deux projets natifs ont reçu le paquet recompilé. Le test Android attend désormais l’identifiant de l’application. |

## Vérifications et points ouverts au 21 novembre

- La suite applicative passe ses 300 tests. Les deux tests de sauvegarde chiffrée et les contrôles PostgreSQL isolés passent, notamment pour les migrations, les politiques par propriétaire et les conflits de révision.
- Dans Chrome, un profil invité neuf a enregistré un résultat, rechargé la page et retrouvé sa valeur en français, en anglais et en arabe RTL à 375 pixels de large. Un second parcours a confirmé la conservation des octets d’un profil illisible, son export et la reprise après suppression confirmée.
- Le client mobile passe TypeScript, la compilation Vite et les tests du paquet. Le module initial pèse environ 369 ko compressés. Le contrôle de soumission attend la recette sur appareils. La compilation native, la signature et les parcours de bout en bout sur téléphones physiques restent ouverts.
- **Versionnage.** Réconcilier les deux historiques Git et publier une branche relue contenant le code web et mobile vérifié. Une reconstruction depuis GitHub doit pouvoir reproduire la livraison. Le compte GitHub connecté disposait alors de la lecture seule.
- **Compte et synchronisation.** Vérifier sur deux appareils l’inscription depuis une vraie boîte mail, la reprise après déconnexion, les modifications concurrentes, l’export et la suppression d’un compte de test dédié. Ces parcours avaient été différés par le propriétaire.
- **Exploitation Supabase.** Le connecteur a refusé la lecture des avis de sécurité et de performance du projet hébergé. Leur état actuel et la restauration d’une sauvegarde de production restent à vérifier. Les vérifications de base effectuées pour cet audit utilisent une instance locale isolée.
